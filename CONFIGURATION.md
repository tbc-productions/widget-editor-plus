## App drawer

Click the current app’s icon in the header to switch between Widget Editor+, Compare+, AI Assistant, Code Search+ and, for administrators, Credit+. Selecting a row uses the current tab; the hover action opens a new tab. Widget Editor+ asks you to save or discard unsaved changes before leaving. Its header remains available in the Open modal and shows **Widget Editor+** until a record is open.

Switching between Widget Editor+, Compare+, Credit+ and AI Assistant carries the saved record when supported. AI Assistant adds it as the primary record and uses that primary record when switching away. Unsupported, unavailable or unreadable records open the destination fresh. Credit+ requires code fields and readable Customer Updates. Unsaved edits and historical version selections do not carry between apps.

## Supported editor records

Use **Open…** and click the dotted record type in the title to switch between the following types. The widget toolbar and panes retain their existing layout; the picker keeps its search and recent-history columns.

| Record type | Table | Code panes |
|---|---|---|
| Widgets | `sp_widget` | HTML template, CSS/SCSS, client controller, link and server script |
| Script Includes | `sys_script_include` | Script |
| CSS | `sp_css` | CSS/SCSS |
| UI Scripts | `sys_ui_script` | Script |
| Angular Providers | `sp_angular_provider` | Script |
| UI Pages | `sys_ui_page` | HTML/Jelly, client script and processing script |
| Angular HTML templates | `sp_ng_template` | HTML template |

**New** follows the selected record type and opens an unsaved record directly in the current Editor+ tab. If there are unsaved changes, choose **Save & Continue**, **Discard & Continue** or **Cancel** before leaving the current record. Dictionary defaults and create permissions apply. Use **Save** to create the record; code-pane saves and local draft recovery become available after the first successful save. Each type has an explicit field list in `WidgetEditorAjax`; unsupported fields are preserved. Name or template ID, booleans and relevant choices appear in the toolbar, with descriptions and other fields under **More fields**. The parent widget of an Angular HTML template is shown read-only.

Save code panes independently, or use the toolbar **Save** for all changed editable fields. The pill bar shows the current name or template ID as you type, with **New <record type>** for unnamed new records. **Revert** in the Unsaved changes popover asks for confirmation, then discards this tab’s edits and reloads the saved record or new-record defaults. Local drafts are recovery copies and never write to ServiceNow automatically. Record and field access checks, protection policies and normal record validation apply to saves. If a changed field has also changed in ServiceNow, saving stops and keeps your local edits for comparison.

In widgets, **Open in Editor+** on related Script Includes, Angular HTML templates and Angular Providers opens the full record editor in another tab. The **More fields** arrow shows Description, API name and Application where available.

Recent history identifies records by table and sys_id, retaining existing widget history. Drafts are separated by record type. Default editor visibility and order in User Preferences apply only to widgets; other record types start with all code panes visible. The Editors menu is hidden when there is only one code pane. Widget-specific actions, related lists, live presence, real-time updates, ES12 controls and SN Utils integration remain in the widget view; other records retain version comparison, Assistant, XML and native-form access.

Existing widget links using `widget_id` continue to work. Links to another record use the same UI Page with `record_table=<supported table>&record_sys_id=<record sys_id>`; for example, `ui_page.do?sys_id=8b2e70458373fe1070b8b5dfeeaad35e&record_table=sys_ui_page&record_sys_id=<record sys_id>`. These links open records for editing and do not execute the target UI Page or script.

## Markdown formatting

`monaco.plus.update_sets.markdown_escape_characters` defaults to `false`, so exported labels and display values retain their punctuation without added backslashes. This replaces the underscore-only setting; the old `monaco.plus.update_sets.markdown_escape_underscores` property is no longer read.

Enable it to escape backslashes, backticks, asterisks, underscores, braces, square brackets, parentheses, hashes, plus signs, full stops, exclamation marks, pipes, angle brackets, tildes and hyphens. These characters can participate in Markdown syntax, depending on the renderer and context. For example, `+` can start a bullet list, although it does not need escaping in a name such as “Widget Editor+”. When enabled, the exporter conservatively escapes every occurrence in labels and display values. Generated bullets, links and emphasis, configured formatting indicators and URL handling remain unchanged.

Edit `monaco.plus.update_sets.markdown_formatting` in **Widget Editor+ → Properties**. Each update-set number has its own literal value, for example `{"new":":new:","deleted":"Deleted","update_set":{"1":":one:","2":":two:","10":"TEN"}}`. The shipped property lists emoji for numbers 1–10. Add further number keys as needed.

Emoji in the formatting JSON are stored as Unicode escapes (for example, `\ud83c\udd95` for 🆕) to preserve them through property storage and XML transport. They appear as emoji in the exported Markdown.

Empty or unspecified set numbers have no indicator. Use `{"new":"","deleted":"","update_set":{}}` to hide all three indicator types. There are no default formats or placeholders. Values are used beside records and in the update-set legend, with set markers appearing only for multiple sets. Custom marker text and intentional Markdown formatting remain intact. Deleted record names retain strikethrough. Context-only records use the configured marker without automatic italics, keeping links and additional values simpler for Markdown editors.

Additional values use `"display_field_separator":","` and `"display_field_wrapper":"()"`, producing `(value one, value two)`. The separator gets a trailing space for readability unless it is empty or already ends in whitespace. The wrapper is two characters, such as `[]`, or an empty string for no wrapper. `"context_indicator":"↪"` controls both context-only record prefixes and the explanatory footer; an empty string hides the symbol. The symbol is stored as a JSON Unicode escape in the shipped default.

## Markdown primary display fields

In **Widget Editor+ → Properties**, Enter comma-separated primary fields for ordered fallbacks, or period-separated fields to combine their values with a period. Empty or unreadable fields are skipped. A field is shown only once: fields used in the primary value are omitted from additional values, and repeated fields are ignored.

Per-table properties use `monaco.plus.update_sets.markdown_display.<table>`. Set `display_value` to `name,sp_widget` for fallbacks or `name.element` to join the two fields. Periods in primary fields refer to separate fields on the same record, not reference dot-walks. Additional fields still support reference dot-walks.

The default `monaco.plus.update_sets.markdown_display.sys_dictionary` uses `{"display_value":"name.element","additional_fields":"column_label,internal_type"}`, producing names such as `incident.short_description` with the column label and internal type as additional values. A table-level dictionary entry with no element displays only its table name as the primary value.

The default `monaco.plus.update_sets.markdown_display.sp_instance` uses primary fallbacks `name,sp_widget` and additional field `sp_widget`. An instance with a name shows its widget separately; an unnamed instance uses the widget as its primary name without repeating it.

### Embedding Monaco on Any Form Field

`monaco_plus_bootstrap` isn't limited to Widget Editor+ itself — add it as a UI Script dependency on an `onLoad` Client Script for any table/field to mount a full Monaco editor in place of the native textarea, in whatever language you choose:

```javascript
function onLoad() {
    if (typeof SNMonacoPlusBootstrap === 'undefined') {
        return;
    }
    SNMonacoPlusBootstrap.upgradeEditor({
        gForm: g_form,
        field: 'my_json_field',
        language: 'json',
        editorOptions: {
            minimap: { enabled: true },
            tabSize: 4,
        },
    });
}
```

- `field` / `language` — the form field to mount on, and the Monaco language id (`json`, `javascript`, `css`, `scss`, `html`, etc.).
- By default the editor auto-grows with content, like a native expanding textarea, starting from the replaced textarea's rendered height (floored at `125px` — enough room for Monaco's quick-input widget, e.g. F1 — even for a short or hidden/collapsed field) and capped at `maxHeight` (default `'80vh'`) before it scrolls internally.
- `height` — pass a fixed height (a number is treated as px, or a CSS size string like `'40vh'`) to opt out of auto-grow entirely.
- `maxHeight` — override the auto-grow cap (ignored once `height` or `containerStyle` is set).
- `showToggle` — set `false` to omit the toggle-syntax-editor button (default: `true`).
- `editorOptions` — any [`IStandaloneEditorConstructionOptions`](https://microsoft.github.io/monaco-editor/typedoc/interfaces/editor_editor_api.editor.IStandaloneEditorConstructionOptions.html) accepted by `monaco.editor.create()`, applied before the editor is created and taking precedence over the user's synced editor preferences.
- `onEditorReady(editor)` — optional callback given the created Monaco editor instance for further customisation.

Need full control over the container instead? Pass `containerStyle` (a CSS string) — it overrides `height`/`maxHeight` and disables auto-grow.

The bootstrap script lazy-loads `monaco_plus_core` on demand, so completions/IntelliSense for the chosen `language` come free without any additional wiring.

## Background code analysis

Widget Editor+ and Assistant use `widget_editor_code_analysis` as a same-origin browser Web Worker to extract code dependencies without running the code. Widget Editor+ uses it for Script Include and injected Angular provider discovery. Monaco language services and ESLint retain their existing workers; custom JSDoc parsing and Angular template validation remain unchanged.

Assistant offers a history button in each record’s **Actions**, including the primary record, without selecting an update set. The button stays highlighted while enabled, and a **+ Previous** badge identifies included history; its tooltip shows the source update set. The choice is remembered with the selection and includes the preceding Customer Update snapshot, skipping the latest snapshot, in the context XML and token estimate. Graph cards offer the same history button. Missing history and failed lookups are identified separately; toggle the button off and on to retry a failed lookup. Blocked record data and table structure exports do not offer this option. The sidebar option continues to include snapshots from before each selected update set.

Assistant loads readable source and configured relationships in batches of up to ten records, with at most three batches in progress. The worker extracts Script Include, table, property, event, integration, flow and provider candidates. The server validates candidates, resolves them with `GlideRecordSecure` and checks whether the source changed during analysis. Changed sources are scanned again on the server. Configured relationship rules and Choice Set discovery retain their existing behaviour. Dictionary metadata, table hierarchies, relationship configuration and identical lookups are reused only within each server request.

Each page shares identical pending analysis jobs and retains up to 32 analysis results, capped at two million characters of cache keys. The cache stays in memory and clears when leaving the page. Worker errors or a 30-second timeout clear pending jobs so later scans can retry; Assistant falls back to server discovery and Widget Editor+ to its existing local scanner. Editor name lookups retain their batches of 50 and now share pending checks, with failed checks remaining retryable. Assistant also shares overlapping XML fetches; completed exports still fetch current XML rather than reuse a previous snapshot.

## User Preferences
User preferences (including editor themes, Assistant visibility, and Debug Menu settings) persist in `localStorage` and synchronise to the ServiceNow instance as `sys_user_preference` records under `monaco_plus.user_prefs`.


### Local draft autosave

In **User Preferences → Editor**, set **Auto-save local drafts** to an interval in whole seconds. The default is **30**; **0** turns automatic capture off, including capture when leaving the tab. **Keep drafts for** below it sets retention in whole days (minimum **1**, default **7**). Both preferences synchronise through `monaco_plus.user_prefs` and are included in preference exports and imports.

For widgets already saved to ServiceNow, drafts capture changed widget fields, open Angular templates, providers and Script Includes, and unfinished Option Schema and Demo Data edits. Capture also runs when the tab becomes hidden or the page is left. Brand-new widgets and read-only version views are excluded. Capture is silent unless browser storage fails. When autosave is enabled, the Unsaved changes popover shows when the current draft was last saved in this browser.

After reopening a widget, the **Local drafts found** info pill appears on the left of the alert bar. Select a draft by its last-edited time and changed-field summary, then choose **Compare**, **Restore** or **Discard**. The newest draft is selected initially. When the browser reports `document.wasDiscarded`, the editor automatically restores that tab’s draft and shows **Unsaved changes** instead. If the tab cannot be identified, automatic restoration requires a single recovery draft; otherwise the Local drafts found pill remains available. Browsers without this signal use manual recovery. Previous recovery drafts remain available while editing, even when automatic capture is off. If another tab changes a draft before it is discarded, the editor keeps it available and asks you to review its latest contents. Discarded copies are not recreated by their original tab until its content changes. Restoring loads changes into the editor without saving to ServiceNow. Compare opens the existing Compare+ modal, with a record selector when a draft includes related records. Conflicting saved content or current edits require review before restoration. Normal access checks still apply. Successful saves remove recovery content that matches the saved record, including copies from earlier sessions. Unsaved JSON, related-record changes and newer typing remain recoverable. Older drafts with different content are retained: age alone does not prove their changes were saved. Failed saves preserve drafts. Subsequent unsaved edits can create a fresh draft. Setting the interval to 0 does not itself remove existing recovery copies.

Drafts are separated by instance, user, widget and open page. Expired drafts are removed across this user’s widgets when the editor opens and before draft writes, based on the last content change. The current tab’s working copy is retained while it is open. Drafts are also removed when saved or discarded; clearing site data removes them. Local storage is not an encrypted store for sensitive content. Explicitly cancelling an Option Schema or Demo Data dialog discards its edits.

## Credit+

Credit+ is available to administrators in the Widget Editor+ application menu below Code Search+, and in the list context menu on `sys_update_xml`, including conventional Updates related lists on widgets. It opens the right-clicked row; where a row ID is not supplied by the platform, exactly one checked customer update is required. The selected update and code fields are validated on the server at launch. The earlier preview form link is disabled.

The global `WidgetEditorCreditAjax` Script Include is accessible from its own application scope. It validates launches and supplies record, field and history metadata; attribution and Statistics analysis run only in the browser worker using Table API payloads. Compare+ requests read-only Customer Update snapshots from the same Script Include. It does not read `sys_update_version` or track intermediate edits within an update set. Launch links use `sysparm_update`. The UI Page (`widget_editor_credit`) and client-callable Script Include have admin ACLs; every public method also checks the role. Historical records remain read-only and historical code is never saved, reverted or executed.

The viewer uses the platform's AngularJS runtime for page state, field containers and Statistics, with directives managing Monaco and Select2. Statistics and activity controls use the platform’s FontAwesome 4 stylesheet. The viewer follows Compare+'s themed header with searchable Select2 table and record pickers, a themed Update set dropdown and read-only Monaco editors, with a plain text fallback if Monaco cannot load. The table picker lists update-synchronised tables with supported code fields, including inherited fields. Record search uses the table display field and both pickers page their results. Choosing a table clears the record; choosing a record loads its newest Customer Update by Customer Update timestamp. Records without Customer Updates show Compare+’s centred, themed empty state. Deleted records remain accessible through Customer Update launches. Widget records offer **Open in Widget Editor+**; record, Customer Update and update-set links open through `nav_to.do?uri=`. Selection updates both the content-frame URL and the outer ServiceNow URL, so refreshes and bookmarks retain the chosen update set. History entries include the record name and current selection. All supported fields appear as independent collapsible sections, sorted by label, and start collapsed on load and after an update-set change. Fields with no code remain disabled. Fields unavailable in the selected snapshot show an **Unavailable** label; empty fields show **0 lines**. The initial request returns field and update-set metadata without calculating or returning code attribution. Expanding a field loads its history and scrolls its heading into view once its editor is ready; collapsing it disposes its Monaco editor. Reopening uses cached data for the same update set. Multiple fields can remain open together. Right-click a Created by or Update set value (or use Shift+F10, Enter or a tap) for a ServiceNow context menu. Show matching and Filter out apply to that field only; small removable filters keep clearing available even with no matching rows. Created by and Update set values use link colour, a dotted underline and a hand cursor to indicate their menus. Monaco keeps the complete code model and original line numbers while hiding non-matching lines. The icon-only **Grouped view** and **Column view** buttons beside Whitespace settings switch between grouped attribution (the default) and separate date, author and update-set columns for each line. The selected button is highlighted. Switching views keeps loaded code, filters and comparisons. View and whitespace choices are saved together under `credit` in the shared Widget Editor+ user preferences and included in preference exports and imports. Explicit URL options take precedence when opening a link. Syntax colouring, line numbers, selection and find accompany grouped attribution showing the author, update set and timestamp. Each attribution block shows the author once beside an avatar, with the update set and timestamp below. Missing photos use coloured initials. A coloured side marker, a small gap and a 1px dotted separator across attribution and code distinguish blocks in light and dark themes. Attribution details stay visible at the top of the code pane while scrolling within their group, then give way to the next group. Short blocks reserve enough space for the two-line attribution without changing the code or its line numbers. Code keeps its normal background, and Quick compare retains its change highlighting. Empty code is indicated in a full-width table row. Drag the divider or use its arrow keys to resize attribution and code across all field tables. Long attribution values use ellipses with full-value tooltips. Monaco owns the line positions, font metrics and scrolling, including after resizing or zooming. Wrapping and folding are disabled to keep attribution aligned. On narrow screens the time remains available in attribution tooltips and comparison metadata. Record loading updates the title immediately and notifies the ServiceNow shell. Page and parent-frame titles show the record name, table and instance product name; the shared `we_history_sync` helper records History entries with **Credit+** as the primary value and the record name as the secondary value. History URLs retain the last expanded field.

Code fields come from the table's effective elements, including inherited dictionary fields, and are sorted by field label ascending. Supported types include CSS, JavaScript, HTML, JSON and condition fields. CSS fields, including Style Sheet records, use CSS colouring. HTML templates use HTML colouring, JavaScript conditions use JavaScript colouring, and encoded conditions remain plain text. Set links come directly from each Customer Update's `update_set` or `remote_update_set`; missing or unreadable sets show a dash. XML parsing reads the target record's direct children, including empty fields, CDATA and XML entities, and ignores companion application-file records. Invalid, duplicate-target and DTD/entity declaration payloads fail safely.

History is selected by update name. Every Customer Update keeps its own sys_id; duplicate update-set names and repeated snapshots caused by reverts are supported. Snapshots are ordered by Customer Update `sys_updated_on`, then `sys_created_on`, `sys_mod_count` and sys_id. Missing update times fall back to creation time; the ID gives stable ordering when metadata cannot distinguish snapshots. This is a deterministic best effort, not proof of the original order for indistinguishable imported timestamps. The dropdown shows Customer Update time, set name and Customer Update author; line attribution uses the captured source author/time after loading the field. Metadata requests do not parse historical payloads. Malformed, unreadable, oversized or field-missing intermediate snapshots interrupt attribution; available code still displays. Payloads identifying another record remain an error. Unknown set references remain separate snapshots.

Attribution describes changes between available update-set snapshots, not individual edits or complete authorship. The earliest snapshot is a baseline. Authors come from payload `sys_updated_by`, falling back to the Customer Update's `sys_updated_by`. Imported metadata can identify source authors or importers; fallback times can reflect import or later update activity. Missing snapshots, intermediate edits within a set and revert/branch relationships cannot be reconstructed. Explicit DELETE snapshots use Customer Update author/time metadata because their XML can retain the previous editor's metadata.

By default, the diff ignores all whitespace. The whitespace popover also offers exact matching, ignoring changes in the amount of whitespace, or ignoring trailing whitespace only. The setting is saved in the URL and shared user preferences and recalculates open attribution fields and Statistics from the shared history cache; it does not change the displayed code or Quick compare/Compare+ diffs. The diff skips unchanged prefixes and suffixes. Unique unchanged lines split large comparisons into smaller sections (patience matching). Remaining sections use Myers matching for repeated lines or sparse longest-common-subsequence matching (Hunt–Szymanski) for sparse matches, then match unmatched moved blocks and unique meaningful lines without reusing origins for copies. Normalised lines are reused between consecutive snapshots. Attribution and Statistics matching run in a same-origin browser Web Worker, keeping the page responsive. The server validates admin access and supplies the ordered Customer Update identifiers, supported fields and limits. The browser retrieves payloads through the same-origin Table API in batches of up to 100 records, with the platform enforcing table and field access. It checks record identity, timestamps, modification counts and update-set references against the server metadata, parses the XML and keeps only supported code fields in memory. History retrieval starts in the background after record metadata loads. Collapsed field headings show line counts as soon as the selected payload is available. Fields, Statistics and quick comparisons share the same history; attribution and Statistics calculations still run only when requested. Changing update sets keeps the cache when the history fingerprint is unchanged. Reload, changing records or leaving the page clears it and cancels pending retrieval. A bounded cache prioritises the selected snapshot and recent history; selecting an evicted snapshot fetches history again with that snapshot prioritised. The worker retains the previous snapshot and current attribution while calculating. Changing records, reloading or destroying the view terminates its workers; failures remain retryable. Repeated delimiters and ambiguous fragments are handled conservatively. With the default setting, whitespace inside strings, comments and templates is also ignored; this can hide meaningful literal changes. Original code is always displayed. The **Update set** selector includes all available sets for the record, newest first. Choosing a set loads its metadata and collapses the fields; expanding a field loads its code and attribution; the URL follows the selection for reload and History links. The Compare+ menu item opens read-only Compare+ in a new tab for that Customer Update and the immediately preceding update set. Quick compare replaces the field editor with a read-only inline diff from the row’s update set to the selected update set; Stop comparing sits immediately beside the field label in the table header and returns to attribution. Loading messages appear below the header. Comparisons use Customer Update payloads directly, including retrieved sets; the first snapshot compares with an empty baseline. Missing, unreadable or ambiguous snapshots return an error. Both comparison menu items are disabled for the selected set; self-comparisons are disabled and rejected on the server. Credit+ retains its page title and History entry.

Admins can open Credit+ for a supported saved record from the app drawer. In Credit+, the Open in Widget Editor+ split button also offers Open in Widget.

Credit+ limits are positive integer system properties in the **Widget Editor+** category. They are installed only on first install, so application upgrades preserve administrator settings. Invalid or non-positive values use the defaults. XML limits count characters, not encoded bytes.

| Property | Default | Effect |
|---|---:|---|
| `monaco.plus.credit.max_updates` | 5,000 | Maximum retained Customer Updates. Newest updates and the selected update remain available when capped. |
| `monaco.plus.credit.max_payload_chars` | 20,000,000 | Maximum characters in one XML payload. Oversized historical payloads are skipped; an oversized selected payload must be allowed by raising this value. |
| `monaco.plus.credit.max_history_chars` | 100,000,000 | Maximum extracted code characters retained in the browser history cache (the selected snapshot is always retained). |
| `monaco.plus.credit.max_lines` | 50,000 | Maximum lines per field for matching. Larger code still displays with partial attribution. |
| `monaco.plus.credit.diff_work` | 20,000,000 | Matching work units per browser comparison, including retained traceback links. |
| `monaco.plus.credit.request_timeout_seconds` | 180 | Timeout for Table API requests, field/statistics loading and worker calculations, capped at the browser timer maximum. Platform transaction limits still apply. |
| `monaco.plus.credit.statistics_batch_size` | 10 | Retired; no longer read. The Table API browser cache uses up to 100 records per retrieval request. |

When a history or matching limit is reached, current code remains visible. Uncertain attribution stays blank, and the field reports partial results. Statistics exclude uncertain comparisons rather than inventing additions or removals. Increasing limits allows more work but can increase transfer size, browser memory and calculation duration. Late responses after a timeout or record change are discarded.

The **Statistics** expandable container appears before the code fields and loads statistics on demand, using the Assistant’s themed skeleton bars while calculating (static with reduced motion). Four leaderboards rank Created by users and update sets with positive totals, with gold, silver and bronze rank icons for the first three places for lines added and removed: Builders/Destroyers for people and Expansions/Demolitions for update sets, across all available update sets and supported code fields, including sets after the selected snapshot. A replacement counts as one removal and one addition; the first snapshot counts as additions. Statistics calculate only when opened, reusing or loading the shared history cache. User references, profile photos and record creation metadata are resolved by one lightweight admin-only server request. Totals are calculated in the browser worker and grouped by case-insensitive username and update-set table/sys_id, so equal names remain distinct and reverts do not inflate the update-set count. Changed histories require Reload. Whitespace/move matching limits apply per comparison. Missing, oversized or unreadable snapshots interrupt comparison; mismatched target records still fail. These are captured-snapshot totals, not individual-edit counts. Unknown or unreadable set references are identified separately from the update-set count.

Statistics also show record age in whole days, founder, contributor count, total lines created/destroyed, busiest field, biggest makeover and busiest month (all ranked by additions plus removals), plus **Longest quiet spell**, the greatest whole-day gap between consecutive recorded updates.
